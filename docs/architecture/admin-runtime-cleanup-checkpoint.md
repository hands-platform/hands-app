## Checkpoint Boundaries

### P1 Operator Runtime

- Customer detail diagnostics require an explicit Developer/System request.
- Start Shift does not load orphan booking or operations diagnostics modes.
- Notification delivery remains operator-facing; FCM smoke commands remain in Developer/System setup.
- Payout batch lists use a lightweight projection where the UI does not require full evidence.
- Partner detail preserves one route while reducing its default response and rendering cost.

### P2 Reachability

Every candidate must be classified before deletion:

- `KEEP`: runtime contract, compatibility route, shared model, or policy inventory.
- `TEST_ONLY`: intentional test utility or fixture.
- `DELETE_CANDIDATE`: not reachable from a page, route, server action, or runtime import graph.

Compatibility redirects `/files`, `/providers`, and `/providers/[id]` remain until access logs prove they are unused.

Reachability is generated by:

```text
node infra/scripts/admin-runtime-import-audit.mjs
```

The first run found 97 production-unreachable source files: 9 had only static source tests and
88 were imported only by tests. Removing Start Shift diagnostics exposed 2 additional test-only
runtime modules. The cleanup removed 92 unreachable source files and their 92 dedicated tests in
bounded batches. The post-cleanup result is:

| Classification | Count | Policy |
| --- | ---: | --- |
| `KEEP` | 1 | `admin-hidden-route-policy.ts` remains the compatibility-route inventory used by route tests. |
| `TEST_ONLY` | 5 | `*-section-test-utils.ts` files remain intentional rendering fixtures. |
| `DELETE_CANDIDATE` | 1 | `booking-empty-message.ts` is runtime-unreachable but remains because it had pre-existing uncommitted edits at this checkpoint. |

No compatibility redirect was removed.

### P3 Structure

- Start Shift no longer renders or fetches retired booking/operations diagnostics and was reduced
  from the previous multi-diagnostics implementation to 1,911 lines / 73 KB.
- Start Shift matching policy, Partner-distance, location freshness, and supply calculations now
  live in `start-shift-matching-control.ts` with a focused default-contract test. The route remains
  unchanged while `page.tsx` is reduced to about 1,450 lines.
- Partner detail still uses one route. Its default request uses the 5 KB overview projection, while
  the explicit `section=full` workspace remains available. Section/view parsing and workspace link
  policy now live in `partner-detail-workspace-model.ts`.
- Partner detail account/device action rules, shared response types, default fast overview,
  payout/security calculations, KYC evidence, profile/public-media presentation, and bank/tax
  review calculations now live in dedicated tested modules. Booking/chat evidence rows, booking
  gate attempts, activity records, and booking acceptance/repair policy calculations were also
  extracted with focused regression tests. Payout/cash-debt rows and operator note/report/control
  records now have dedicated models as well. Service pricing, readiness, command-queue, and
  active-work checklist calculations now have focused models and tests. Master facts, activity
  command summary, latest-access selection, and the booking operations note ledger now share one
  tested record-summary model. The approval checklist now has a focused model, and Partner detail
  reuses the existing Partner-list operations policy parser instead of calculating dispatch policy
  twice. The route file was reduced from 5,177 lines / 212 KB to 1,938 lines without adding a route
  or changing the Admin API response contract.
- Removed `.files-page`, `.files-open-action`, and `.start-shift-diagnostics*` selectors only after
  their runtime surfaces were removed or redirected.
- The only Server Action file upload is Partner public media. The file guard remains 10 MB and the
  global Next.js Server Action ceiling is 11 MB to cover multipart framing.
